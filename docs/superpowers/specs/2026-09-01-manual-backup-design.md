# Manual Backup & Restore — Design

Date: 2026-09-01
Status: Approved for implementation

## Goal

Let the user export all of their data to a single JSON file and import it
back later, on the same or a different device. This is Phase 1. A later
separate spec covers automatic Google Drive account sync (Phase 2).

## Scope

In scope:

- Export a backup file containing custom tasbih, custom routines and their
  steps, favorite flags on built-in tasbih, session history, and app
  preferences.
- Import a backup file with **merge** semantics: backup items are upserted
  alongside current data; on primary-key collision the backup wins.
  Anything created since the backup is kept.
- A new "Backup" section in the Settings screen with Export and Import rows.
- Delivery through the Storage Access Framework (system create-document and
  open-document dialogs). No storage permissions, no network.

Out of scope (Phase 2, separate spec):

- Google Sign-In, Drive AppData API, WorkManager periodic sync, last-synced
  timestamp, conflict resolution, backup file encryption.

## Backup file format

A single JSON object. MIME type `application/json`, suggested file name
`dhikr-backup-<yyyy-MM-dd>.json`.

```
{
  "format": "dhikr.backup",
  "version": 1,
  "createdAt": <epochMillis>,
  "appVersionName": "1.0",
  "customTasbih": [
    { "id", "name", "arabic", "transliteration", "translation", "note",
      "source", "lapTarget", "lapCount", "dailyGoal", "isFavorite",
      "createdAt", "updatedAt" }
  ],
  "builtInFavorites": [ "<tasbihId>", ... ],
  "customRoutines": [
    { "id", "name", "createdAt", "updatedAt",
      "steps": [ { "tasbihId", "stepOrder", "targetCount" } ] }
  ],
  "sessions": [
    { "tasbihId", "routineId", "count", "startedAt", "endedAt" }
  ],
  "preferences": {
    "dailyGoalTarget", "themeMode", "hapticMode", "reducedMotion",
    "dynamicColor"
  }
}
```

Rules:

- `isBuiltIn` / `isPreset` are never serialized. Every restored tasbih and
  routine is written as custom (`isBuiltIn = false`, `isPreset = false`).
- Autogenerated keys — `session.id`, `routine_step.stepId` — are omitted and
  regenerated on insert.
- `builtInFavorites` holds the ids of built-in tasbih the user has
  favorited. Re-applied with `setFavorite` on restore.
- A session whose `tasbihId` is neither a known built-in nor present in
  `customTasbih` is skipped on import (foreign-key safety) and counted in
  the result.
- `preferences` values are stored as the enum `name` strings for theme and
  haptics, matching what `AppPreferencesRepository` persists.
- The JSON parser uses `ignoreUnknownKeys = true` so a newer minor format
  stays readable.

### New DAO methods

`TasbihDao`:

- `@Query("SELECT * FROM tasbih WHERE isBuiltIn = 0") suspend fun getAllCustom(): List<TasbihEntity>`
- `@Query("SELECT id FROM tasbih WHERE isBuiltIn = 1 AND isFavorite = 1") suspend fun getBuiltInFavoriteIds(): List<String>`
- `@Query("SELECT id FROM tasbih") suspend fun getAllIds(): List<String>`
- `@Insert(onConflict = OnConflictStrategy.REPLACE) suspend fun upsertAll(items: List<TasbihEntity>)`

`RoutineDao`:

- `@Transaction @Query("SELECT * FROM routine WHERE isPreset = 0") suspend fun getAllCustomWithSteps(): List<RoutineWithSteps>`
- `@Insert(onConflict = OnConflictStrategy.REPLACE) suspend fun upsertRoutine(routine: RoutineEntity)`
  (steps reuse the existing `replaceSteps`)

`SessionDao`:

- `@Query("SELECT * FROM session") suspend fun getAll(): List<SessionEntity>`

### AppPreferencesRepository additions

One-shot getters over the existing flows, used by the backup repo:

- `suspend fun snapshot(): PreferencesSnapshot` — reads `dailyGoalTarget`,
  `themeMode`, `hapticMode`, `reducedMotion`, `dynamicColorEnabled` with
  `.first()`.
- `suspend fun restore(snapshot: PreferencesSnapshot)` — calls the existing
  setters. Unknown enum strings fall back to the same defaults the flows
  already use.

## Data flow

### Export

1. User taps Export. The `CreateDocument` launcher opens with the suggested
   file name.
2. On a returned `content://` Uri, `BackupViewModel` moves to `Working` and
   calls `repo.createBackup()`, which reads every source and returns the
   JSON string.
3. The VM writes the string to `contentResolver.openOutputStream(uri)` in
   UTF-8, then moves to `Success`.
4. A cancelled dialog (null Uri) returns silently to `Idle`.

### Import

1. User taps Import. The `OpenDocument` launcher opens filtered to
   `application/json`.
2. On a returned Uri, the VM reads the text from
   `contentResolver.openInputStream(uri)` and calls
   `repo.restoreBackup(text)`.
3. `restoreBackup`:
   1. Parse JSON. If `format != "dhikr.backup"` or `version > CURRENT`,
      return an error outcome — no mutation.
   2. `database.withTransaction { ... }`:
      - `tasbihDao.upsertAll(customTasbih as entities with isBuiltIn=false)`
      - re-apply `builtInFavorites`: for each id, `setFavorite(id, true)`
      - for each custom routine: `upsertRoutine(...)` then
        `replaceSteps(routineId, steps)`
      - build the set of valid tasbih ids
        (`tasbihDao.getAllIds()` after the upsert); insert each session
        whose `tasbihId` is in that set, skip and count the rest
   3. Outside the transaction: `preferencesRepository.restore(snapshot)`
      (best effort).
   4. Return `RestoreOutcome.Success(tasbihAdded, routinesAdded,
      sessionsAdded, sessionsSkipped, preferencesApplied)`.
4. The VM renders a one-line summary in `Success`, e.g.
   "Restored 4 tasbih, 2 routines, 310 sessions (2 skipped)."

## Error handling

| Situation | Behavior |
|---|---|
| SAF dialog cancelled (null Uri) | Silent return to `Idle`. |
| `openInputStream` / `openOutputStream` null or throws | `Error("Couldn't read the file")` / `Error("Couldn't write the file")`. |
| JSON parse failure or wrong `format` | `Error("This isn't a valid Dhikr backup file")`. No DB mutation. |
| `version` newer than current | `Error("This backup was made by a newer version of the app")`. |
| Exception inside the Room transaction | Whole Room portion rolls back. `Error("Restore failed, your data is unchanged")`. |
| Preferences write fails after Room committed | `Success` with `preferencesApplied = false`; summary notes settings were not restored. |
| Session with unknown `tasbihId` | Skipped, counted in `sessionsSkipped`, not an error. |

## Testing

Instrumented `BackupRepositoryTest` (in-memory Room + a test DataStore):

- Round trip: seed custom tasbih, custom routine with steps, built-in
  favorite, sessions, non-default preferences → `createBackup` → wipe all →
  `restoreBackup` → assert every source matches the pre-backup state.
- Merge: a custom tasbih with the same id as one in the backup is
  overwritten by the backup; an unrelated custom tasbih is untouched.
- Orphan session: a backup session referencing a missing tasbih is skipped
  and reported in `sessionsSkipped`; valid sessions still import.
- Malformed JSON: error outcome, database unchanged (assert row counts
  before and after are equal).
- Version guard: `version = 999` returns the newer-version error, no
  mutation.

Unit `BackupModelsTest`:

- Serialize then deserialize a fully populated `BackupFile`; assert equality.
- JSON with an extra unknown key deserializes without throwing.

  pin to the newest 1.7.x at implementation time)
- plugin `kotlin-serialization = { id = "org.jetbrains.kotlin.plugin.serialization", version.ref = "kotlin" }`
- library `kotlinx-serialization-json = { group = "org.jetbrains.kotlinx", name = "kotlinx-serialization-json", version.ref = "kotlinxSerialization" }`

Apply the plugin in `app/build.gradle.kts` and add the library
`implementation`.

## About-screen text

The Settings "About" lines ("works offline", "no account", "never
uploads") stay accurate: manual backup writes a file the user controls and
uploads nothing. That text changes only when Phase 2 Drive sync lands.
